🧩 插件开发指南

从零开始创建自定义 Skill、Hook、Command，打包发布为 Plugin

1

自定义技能 (Skill)

Skill 是 Claude Code 最核心的扩展单元。一个 Markdown 文件 + YAML 元数据 = 一个专业技能。

🎯 Hello World：创建你的第一个技能

1

创建目录和文件

# 在项目根目录下 mkdir -p .claude/skills/hello touch .claude/skills/hello/SKILL.md
2

编写 SKILL.md

--- name: hello description: 向用户问好，并显示当前项目信息 allowed-tools: - Bash - Read --- # Hello 技能 当用户说「打个招呼」或调用 /hello 时，执行以下操作： 1. 读取 package.json（如果有的话） 2. 运行 `whoami` 获取当前用户 3. 输出: "你好 {用户名}！欢迎来到 {项目名}。"
3

加载并使用

# 重新扫描技能目录 /reload-skills # 试试触发你的技能 /hello

✅ 完成！Claude 检测到 /hello 后会加载 SKILL.md 中的指令并执行。

📋 SKILL.md 元数据字段速查

字段类型说明
namestringkebab-case 名称，最长 64 字符。定义了 /name 斜杠命令
descriptionstring第三人称描述，最长 200 字符。Claude 用来自动匹配和触发技能
argument-hintstring斜杠菜单中的参数提示，如 [feature-name]
disable-model-invocationbooleantrue = 只能手动 /name 调用，Claude 不自动触发
user-invocablebooleanfalse = 隐藏在 / 菜单中（只能模型调用）
allowed-toolsstring[]无需权限弹窗即可使用的工具列表
disallowed-toolsstring[]显式禁止使用的工具列表
modelstring可选模型覆盖：sonnet / opus / haiku
contextstringfork = 在隔离子代理上下文中运行
💡 渐进式加载策略：会话启动只加载 name + description（~100 tokens）。触发技能时才加载完整 SKILL.md。references/ 目录下的文件仅在需要时加载。保持 description 精准以优化自动匹配。
2

自定义 Hook

Hook 在特定事件前后自动执行脚本——相当于 Claude Code 的「自动化触发器」。

📡 常用 Hook 事件类型

事件触发时机典型用途
PreToolUse工具调用之前审批敏感操作、记录审计日志
PostToolUse工具调用成功后自动格式化、运行测试
PostToolUseFailure工具调用失败后错误通知、自动重试
UserPromptSubmit用户提交消息时注入上下文、规则检查
SessionStart会话启动时环境检查、项目初始化
SessionEnd会话结束时清理临时文件、上传日志
PreCompact上下文压缩前保存关键信息
Notification后台任务完成时桌面通知

🔧 实战 A：提交前自动运行测试

配置位置：.claude/settings.json → hooks
// .claude/settings.json { "hooks": { "PreToolUse": [ { "matcher": "Bash(git commit*)", "hooks": [ { "type": "command", "command": "pytest --quiet && echo 'Tests passed'" } ] } ] } }

效果：每次 git commit 前自动运行 pytest。测试不通过则阻止提交。

🔧 实战 B：编辑后自动格式化

{ "hooks": { "PostToolUse": [ { "matcher": "Edit", "hooks": [ { "type": "command", "command": "prettier --write ${CLAUDE_TOOL_INPUT.file_path} 2>/dev/null || true" } ] } ] } }

效果：每次 Claude 编辑文件后，自动用 Prettier 格式化。用 || true 确保格式化失败不阻断流程。

3

自定义命令 (Command)

旧版扩展方式——与 Skill 类似但更简单。适合快速创建一个斜杠命令。

Command vs Skill 对比

维度CommandSkill
文件位置.claude/commands/<name>.md.claude/skills/<name>/SKILL.md
元数据无 YAML 前置有 YAML 前置（9 个字段）
自动触发只能手动 /nameClaude 可自动匹配触发
优先级低于同名 Skill高于同名 Command
推荐场景快捷脚本、团队内部命令复杂工作流、可分享的专业技能

📌 建议：新项目优先使用 Skill。Command 主要用于兼容旧版或极简场景。

4

打包发布 Plugin

将多个 Skill + Hook + Command 打包为一个 Plugin，通过 GitHub 分享给团队或社区。

📁 Plugin 目录结构

my-plugin/
├── .claude-plugin/
│   └── marketplace.json   ← 插件清单（必需）
├── skills/
│   ├── my-skill/
│   │   └── SKILL.md
│   └── another-skill/
│       └── SKILL.md
├── commands/
│   └── deploy.md
├── hooks/
│   └── pre-commit.json
├── agents/
│   └── reviewer.md
└── README.md

📝 marketplace.json 示例

{ "name": "my-awesome-plugin", "description": "My custom dev tools", "version": "1.0.0", "plugins": [ { "name": "my-awesome-plugin", "description": "A collection of productivity tools", "source": "./plugins/my-awesome-plugin", "version": "1.0.0" } ] }

🚀 发布流程

1 创建仓库
2 Push GitHub
3 团队安装
# 团队成员安装你的插件 claude plugin marketplace add your-username/my-awesome-plugin claude plugin install my-awesome-plugin@my-awesome-plugin
🌐 社区市场：想让更多人使用？发布到 Awesome Claude Plugins 聚合目录，或注册到 claude-night-market。
