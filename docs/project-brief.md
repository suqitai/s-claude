# Claude 使用说明书 — 项目简报

## 问题陈述
Claude Code 拥有 50+ 命令、10+ 内置技能、丰富的插件生态，但缺乏一份**结构化、渐进式的中文使用说明书体系**。新手不知道从何入手，高级用户找不到自定义开发的最佳实践。

## 目标

1. **入门指南** — 5 分钟快速上手，覆盖安装、首次对话、核心概念
2. **技能速查** — 已有 Skills Manual 的增强版，增加搜索和分类筛选
3. **实战工作流** — attune、spec-kit 等核心插件的实际使用场景
4. **开发者指南** — 自定义技能、Hook、插件开发的完整教程
5. **管理指南** — 团队配置、权限策略、MCP 管理

## 成功标准

- [ ] 新用户能在 5 分钟内完成首次有效对话
- [ ] 所有 50+ 命令可在 3 秒内查找到
- [ ] 至少 3 个完整的实战工作流示例
- [ ] 自定义技能开发教程包含可运行示例
- [ ] 整体视觉质量 ≥ 现有 Skills Manual

## 约束

- **技术**: 纯静态 HTML/CSS/JS，零依赖
- **资源**: 单人维护，社区反馈驱动
- **兼容**: 所有页面通过 `<link>` 共享基础样式
- **语言**: 简体中文，技术术语保留英文

## 方案选择

**方案 A — 单页手册增强体系**

```
Claude使用说明书/
├── index.html                 ← 🏠 门户导航（新增）
├── guides/
│   ├── quick-start.html       ← 🚀 5分钟入门（新增）
│   ├── workflow-guide.html    ← 🔧 工作流实战（新增）
│   └── plugin-dev.html        ← 🧩 插件开发指南（新增）
├── manuals/
│   └── skills-manual.html     ← 📋 技能手册（已有，增强）
├── assets/
│   └── style.css              ← 🎨 统一样式（新增）
└── docs/
    └── project-brief.md       ← 📝 本文档
```

## 取舍

| 取舍 | 原因 | 缓解措施 |
|------|------|----------|
| 多文件 vs 单文件 | 便于维护和渐进式阅读 | 共享 CSS，导航栏统一 |
| 静态 vs 动态 | 零部署，双击即用 | 用 JS 实现客户端搜索 |
| 中文 vs 英文 | 目标用户是中文开发者 | 术语保留英文便于对照 |

## 排除范围

- 视频教程（资源需求大）
- 后端 API 服务（保持纯静态）
- 英文版本（Phase 2 考虑）
- 移动端 App（响应式已足够）
